Un lecteur de bibliothèques d’images en C++/GTKmm, avec des sources de données locales, HTTP et hors ligne. Le projet associe interface graphique, tâches de fond, serveur HTTP C++ et indexation PostgreSQL.

Enjeu

Faire évoluer les accès aux données sans dupliquer l’interface

Un chapitre peut être lu depuis le système de fichiers, via une API locale ou depuis un cache hors ligne. Le contrat ScanDataSource place ces modes derrière une interface commune pour conserver les règles de navigation et de progression.

Les opérations longues demandent aussi une organisation propre : le téléchargement expose progression, pause, reprise et annulation pendant que l’interface conserve sa boucle d’événements.

Le serveur local gère le routage HTTP sur sockets POSIX et les données de bibliothèque. L’index PostgreSQL regroupe scans, chapitres, pages et informations de suivi. Le cœur métier peut être compilé séparément de l’interface graphique.

Choix techniques

Structurer les dépendances autour des usages

01 / ARCHITECTURE

Un contrat de données commun

Les modes local, API et hors ligne sont représentés par des implémentations derrière la même abstraction.

02 / RÉACTIVITÉ

Organiser les tâches de fond

La file de téléchargements expose progression et annulation, avec un traitement distinct du thread d’interface.

03 / ACCÈS

Définir un périmètre local

Le serveur comprend des contrôles de chemin, une configuration CORS et des restrictions pour les routes d’administration.

04 / PERSISTANCE

Structurer l’index

PostgreSQL porte le modèle de bibliothèque et les données de progression, de favoris et d’historique.

Démonstration

Tester le cœur sans environnement graphique

La démonstration incluse présente la suite légère : session de lecture, stockage JSON, source de fichiers, synchronisation hors ligne, téléchargements et parsing HTTP. Cette suite est distincte de la validation de l’interface GTK et du serveur PostgreSQL.

Depuis la racine du dépôt, cette configuration compile la cible de tests du cœur sans construire la partie graphique ni le serveur. Les prérequis sont décrits dans le README.

Compiler et tester le cœur

cmake -S . -B build -DSCANGUI_BUILD_GUI=OFF -DSCANGUI_BUILD_SERVER=OFF
cmake --build build --target ScanGUITests
ctest --test-dir build --output-on-failure
